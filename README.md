# Max Payne Passthrough

Мод, который переносит анимации и Euphoria-рагдолл Max Payne 3 в Max Payne 1.
Обе игры запущены одновременно: MP3 работает «движком анимации» — его
марионетки (Макс и враги) проигрывают анимации и физические реакции, а позы
их костей в реальном времени передаются в MP1 и применяются к персонажам MP1.

```
 Max Payne 1 (mp1phys.asi)                    Max Payne 3 (mp3bridge.asi)
 ─────────────────────────                    ───────────────────────────
 события: попадания, смерти,  ── команды ──▶  марионетки: спавн, попадания,
 действия игрока, bullet time                 анимации, Euphoria, time scale
 скелет MP1 ◀─ ретаргетинг ◀── позы костей ── скелеты педов MP3
 Rapier: коллизии с уровнем MP1
```

## Состав

| Путь | Что это |
|---|---|
| `crates/bridge` | Протокол через общую память Windows: снимки поз (seqlock), очередь команд (SPSC), heartbeat. Раскладка одинакова для 32- и 64-битных сборок. |
| `crates/scripthook` | Script Hook для MP3 без import library: поиск функций среди экспортов `ScriptHook.dll` по MSVC-именам с проверкой сигнатур, вызов нативов, типизированные обёртки используемых нативов, таблица костей тела педа MP3. |
| `crates/ragdoll` | Физика рагдолла на Rapier: тела на костях, суставы с лимитами, импульсы пуль, bullet time через фиксированный шаг, слежение тел за целевыми позами с силой 0–1 и ограниченными скоростью и ускорением. В MP1 тела будут следовать позам из MP3, сталкиваясь с геометрией уровней MP1. |
| `crates/pose` | Скелеты и позы без привязки к игре: текстовый формат скелета, перевод координат между мирами игр (оси, единицы, смена правой/левой системы), ретаргетинг поз MP3 на скелет MP1, кандидаты раскладки матриц костей MP1 (`M_Matrix4x3Template<float>`) и выбор раскладки по образцам. |
| `crates/winmod` | Общая обвязка внедряемых DLL: `DllMain`, лог, список модулей, ожидание загрузки DLL, файлы рядом с `.asi`. |
| `crates/peimage` | Экспорты и импорты PE-модуля, загруженного в память; подмена слота IAT для хуков. |
| `crates/mp1` | `mp1phys.asi` для Max Payne 1: мост, сводка потока поз из MP3 в логе и пробы (списки импортов/экспортов, хук `P_VirtualObject::setBoneMatrices`). |
| `crates/mp3` | `mp3bridge.asi` для Max Payne 3: мост и скрипт Script Hook — каждый кадр позы костей игрока и марионеток, команды из MP1 (спавн, попадания, time scale). |
| `tools/recon.py` | Разведка установки игры: версии, хеши, экспорты/импорты, C++-классы, признаки DRM, варианты загрузчика ASI. |

## Этапы

1. **Связь.** Обе DLL загружаются, видят друг друга через общую память.
2. **Разведка.** Найти в MP1 скелет персонажа, кадр игры, попадания и смерти;
   в MP3 — скелеты педов и нативы Script Hook для марионеток. ← сейчас
   (пробы ниже)
3. **Зеркало Макса.** Поза Макса из MP3 применяется к Максу в MP1.
4. **Управление.** Ввод и состояние Макса в MP1 (бег, шутдодж, прицел)
   управляют марионеткой в MP3; синхронизация bullet time.
5. **Враги.** Попадание в MP1 → такое же попадание по марионетке в MP3 →
   Euphoria-реакция и смерть возвращаются в MP1; Rapier удерживает тела от
   прохода сквозь стены MP1.
6. **Механики MP3**, которых в MP1 нет: стрельба лёжа после шутдоджа,
   last stand, bullet cam.

## Разведка

```
python tools/recon.py "C:\Program Files (x86)\Max Payne" --out recon\mp1
python tools/recon.py "<папка Max Payne 3>" --out recon\mp3
```

Скрипт только читает файлы игры. В каждой папке получатся `recon.md` (сводка
для чата) и `recon.json` (полные данные).

## Скелеты и соответствие костей

Найденные разведкой скелеты и соответствие костей хранятся в текстовых
файлах; `#` начинает комментарий, пустые строки пропускаются.

* Скелет: кость на строку, `имя родитель tx ty tz qx qy qz qw` — поза покоя
  относительно родителя; у корня вместо родителя `-`, родитель стоит выше.
* Соответствие: `кость_MP3 кость_MP1` на строку.

Перевод осей задаётся строкой вида `x,-z,y`: для каждой оси MP1 по порядку —
ось MP3 со знаком, из которой она берётся, то есть `p' = scale * (p.x, -p.z, p.y)`.
Раскладку матриц MP1 `pose::matrix::classify` находит по образцам с точностью
до транспонирования поворота; транспонирование проверяется опытом в игре.

## Протокол моста

Версия 2: у позы актёра есть флаги, бит 0 `ROTATIONS_VALID` — повороты
костей измерены; без него повороты единичные и верны только позиции. Кости
актёров MP3 идут в порядке таблицы костей тела `scripthook::BODY_BONES`
(ROOT, PELVIS, позвоночник, голова, руки, ноги); `bone` в команде попадания —
индекс в этой же таблице. Актёр 0 — игрок MP3. Обе DLL должны быть одной
версии протокола, иначе в логе будет
`bridge protocol v1 found, this build speaks v2; update both mods`.

## Сборка

Готовые `.asi` собирает CI: вкладка Actions → последний запуск `build` →
артефакт `maxpayne-passthrough`. Локально (Windows):

```
rustup target add i686-pc-windows-msvc x86_64-pc-windows-msvc
cargo test --workspace
cargo build --release -p mp1phys --target i686-pc-windows-msvc
cargo build --release -p mp3bridge --target i686-pc-windows-msvc
```

Обе игры 32-битные, поэтому плагины собираются только под
`i686-pc-windows-msvc` (под другие цели они пустые).

## Установка

В артефакте CI папки повторяют папки игр:

* **Max Payne 1:** `max-payne-1\scripts\mp1phys.asi` скопировать в
  `<папка игры>\scripts\`. Ultimate ASI Loader (`d3d8.dll`) уже установлен и
  загружает `*.asi` из этой папки — там же лежит
  `MaxPayne.WidescreenFix.asi`. Папка в Program Files требует прав
  администратора.
* **Max Payne 3:** `max-payne-3\mp3bridge.asi` скопировать рядом с
  `MaxPayne3.exe` (`<steam>\Max Payne 3\Max Payne 3\`). Его должен загрузить
  `dinput8.dll` из Script Hook; что это сработало, подтверждает
  `mp3bridge.log`, который появится рядом после первого запуска. Только
  одиночная игра, без сети. Подробности — в разделе «Max Payne 3» ниже.

Проверка связи: запустить обе игры. В `mp1phys.log` должно появиться
`Max Payne 3 connected`, в `mp3bridge.log` — `Max Payne 1 connected`.

## Max Payne 3

Нужны Script Hook (`ScriptHook.dll` 1.0.21.0) и его `dinput8.dll`, который
загружает `*.asi`, рядом с `MaxPayne3.exe`. Script Hook официально
поддерживает только Steam-версии 1.0.0.216 и 1.0.0.255, а у нас 1.0.0.276:
работает ли он на ней, пока не проверено. Пример SDK регистрирует скрипт в
`DllMain`, а `mp3bridge.asi` — позже, из своего потока, когда найдёт
`ScriptHook.dll`; сработает ли так, тоже не проверено.

Как прогнать: запустить MP3, дойти до игрового процесса, несколько секунд
побегать и повертеться (решение о смысле смещений ниже требует движения),
выйти из игры. MP1 можно не запускать.

В `mp3bridge.log` по порядку должны появиться:

1. `bridge open (protocol v2), waiting for Max Payne 1` — мост открыт,
   heartbeat идёт сразу, ещё до Script Hook.
2. `wrote N lines to ...mp3bridge.scripthook-exports.txt`, затем
   `bound scriptRegister, scriptWait, nativeInit, nativePush32 and nativeCall
   of ScriptHook.dll` — функции найдены, их сигнатуры совпали с SDK. Если
   вместо этого `ScriptHook.dll: no export ...` — у этого Script Hook другие
   функции, скрипт не регистрируется; нужен файл экспортов.
3. `calling scriptRegister from the plugin thread (ThreadId(N)); ...`,
   `scriptRegister returned`, затем `script running on thread ThreadId(M)` с
   другим номером — Script Hook запустил скрипт в потоке игры. Нет последней
   строки — регистрация не сработала. `script started on the plugin thread
   inside scriptRegister ...` — Script Hook запустил скрипт прямо в потоке
   плагина; скрипт завершается, не вызвав ни одного натива.
4. `the script beats the heartbeat from now on, once per game frame` — дальше
   heartbeat бьётся раз в кадр игры, и пауза игры для MP1 выглядит как
   отключение.
5. `player ped N: streaming its body bones as actor 0` — игрок найден, его
   позы публикуются.
6. Один из вердиктов о смещениях `GET_PED_BONE_COORDS`:
   `... offsets are bone-local: publishing bone rotations` (повороты костей
   есть, флаг `ROTATIONS_VALID`) или `... offsets are in world axes: no bone
   rotations, publishing positions only`. Пока вердикта нет, публикуются
   только позиции.
7. `wrote the player skeleton to ...mp3bridge.player-skeleton.txt` — один кадр
   скелета игрока в текстовом формате скелетов (см. выше): имена и родители из
   таблицы костей, локальные преобразования из кадра. Иерархия костей в
   таблице — предположение по стандартному скелету педа RAGE; файл нужен,
   чтобы её проверить и составить соответствие костей MP3 → MP1.
8. Каждые 5 с: `script: N frames, X native calls/frame (max Y), P pose frames
   published`.

`PANIC: ...` и `script stopped` означают, что скрипт упал; лог всё равно
нужен.

MP1 пока не отправляет команды. MP3-сторона их уже принимает и проверяет
(неверные id актёров и нечисловые значения отклоняются с записью в лог):
`Spawn` создаёт марионетку в нескольких метрах от игрока (пока одна
модель-заглушка, не больше 4 марионеток), `Despawn` удаляет её, `Hit`
переводит педа в рагдолл и прикладывает импульс к кости, `TimeScale` меняет
скорость игры.
Параметры нативов спавна и попадания в SDK не описаны, выбраны осторожно и
пишутся в лог при каждом вызове.

В `mp1phys.log` каждые 5 с — сводка потока поз: `pose stream: frame N, game
time T s, A actors; actor 0: 24 bones, flags 0x1, ROOT (...), PELVIS (...)`;
нечисловые данные помечаются `NON-FINITE`.

## Пробы (этап 2)

Плагины сами пишут файлы рядом с `.asi` (при каждом запуске заново):

| Файл | Что внутри |
|---|---|
| `mp1phys.log` | Модули процесса, установка хука, подробности первых 16 вызовов `setBoneMatrices` и первого вызова каждого нового объекта (до 64), каждые 5 с — статистика: вызовы в секунду, число объектов, диапазон числа матриц для двух догадок о раскладке аргумента. |
| `mp1phys.exe-imports.txt` | Импорты `MaxPayne.exe`: `dll имя`, импорты по ординалу — `#n`. |
| `mp1phys.e2mfc-exports.txt` | Экспорты `e2mfc.dll`: `ординал rva имя`, по алфавиту. |
| `mp3bridge.log` | Модули процесса, состояние моста и скрипта Script Hook (см. раздел «Max Payne 3»). |
| `mp3bridge.scripthook-exports.txt` | Экспорты `ScriptHook.dll`. |
| `mp3bridge.player-skeleton.txt` | Скелет игрока MP3 из одного кадра; пишется после вердикта о смещениях. |

Хук в MP1 перехватывает импорт `MaxPayne.exe` из `e2mfc.dll`
(`P_VirtualObject::setBoneMatrices`), сначала вызывает оригинал, затем
только читает аргумент и пишет лог. В MP3 ничего не перехватывается: скрипт
Script Hook только вызывает нативы.

**Выключатель:** пустой файл `mp1phys.nohook` рядом с `mp1phys.asi` — хук не
ставится (в логе будет строка `...mp1phys.nohook exists; not hooking`),
списки и мост работают как обычно. Если создавать файл в Проводнике как
текстовый документ при скрытых расширениях, получится `mp1phys.nohook.txt`,
и он не подействует — проверить по этой строке в логе. Если с хуком игра
падает или ведёт себя странно, сначала сохранить `mp1phys.log` от неудачного
запуска (следующий запуск его перезапишет), потом создать этот файл.

Как прогнать:

1. Max Payne 1: загрузить уровень, где видны Макс и враги, поиграть
   минуту (бег, стрельба, шутдодж), выйти из игры.
2. Max Payne 3: дойти до игрового процесса (не только меню), несколько секунд
   побегать и повертеться, выйти из игры.
3. Прислать в чат все шесть файлов из таблицы. В них только имена функций,
   адреса и числа из памяти, без кода и ресурсов игры; в репозиторий их не
   коммитить.

В `mp1phys.log` важны строки `hooked e2mfc.dll ?setBoneMatrices@...` (хук
стоит), `setBoneMatrices call ...` (подробности вызовов) и
`setBoneMatrices: ... calls/s` (статистика). Если вместо них
`no e2mfc.dll import starts with ...`, `not hooking` или `cannot patch`, лог
всё равно нужен.

## Правила

В репозитории только свой код. Файлы игр (ассеты, исполняемые файлы, дампы)
не коммитятся: мод работает с копиями игр пользователя.
