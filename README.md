# Max Payne Passthrough

Мод, который переносит анимации и Euphoria-рагдолл Max Payne 3 в Max Payne 1.
Обе игры запущены одновременно: MP3 работает «движком анимации» — его
марионетки (Макс и враги) проигрывают анимации и физические реакции, а позы
их костей в реальном времени передаются в MP1 и применяются к персонажам MP1.

```
 Max Payne 1 (mp1phys.asi)                    Max Payne 3 (mp3bridge.asi)
 ─────────────────────────                    ───────────────────────────
 события: попадания, смерти,  ── команды ──▶  марионетки: спавн, попадания,
 действия игрока, bullet time                 анимации, Euphoria, time scale
 скелет MP1 ◀─ ретаргетинг ◀── позы костей ── скелеты педов MP3
 Rapier: коллизии с уровнем MP1
```

## Состав

| Путь | Что это |
|---|---|
| `crates/bridge` | Протокол через общую память Windows: снимки поз (seqlock), очередь команд (SPSC), heartbeat. Раскладка одинакова для 32- и 64-битных сборок. |
| `crates/ragdoll` | Физика рагдолла на Rapier: тела на костях, суставы с лимитами, импульсы пуль, bullet time через фиксированный шаг. В MP1 будет сталкивать позы из MP3 с геометрией уровней MP1. |
| `crates/winmod` | Общая обвязка внедряемых DLL: `DllMain`, лог, список модулей, ожидание загрузки DLL, файлы рядом с `.asi`. |
| `crates/peimage` | Экспорты и импорты PE-модуля, загруженного в память; подмена слота IAT для хуков. |
| `crates/mp1` | `mp1phys.asi` для Max Payne 1: мост и пробы (списки импортов/экспортов, хук `P_VirtualObject::setBoneMatrices`). |
| `crates/mp3` | `mp3bridge.asi` для Max Payne 3: мост и пробы (списки импортов игры и экспортов Script Hook). |
| `tools/recon.py` | Разведка установки игры: версии, хеши, экспорты/импорты, C++-классы, признаки DRM, варианты загрузчика ASI. |

## Этапы

1. **Связь.** Обе DLL загружаются, видят друг друга через общую память.
2. **Разведка.** Найти в MP1 скелет персонажа, кадр игры, попадания и смерти;
   в MP3 — скелеты педов и нативы Script Hook для марионеток. ← сейчас
   (пробы ниже)
3. **Зеркало Макса.** Поза Макса из MP3 применяется к Максу в MP1.
4. **Управление.** Ввод и состояние Макса в MP1 (бег, шутдодж, прицел)
   управляют марионеткой в MP3; синхронизация bullet time.
5. **Враги.** Попадание в MP1 → такое же попадание по марионетке в MP3 →
   Euphoria-реакция и смерть возвращаются в MP1; Rapier удерживает тела от
   прохода сквозь стены MP1.
6. **Механики MP3**, которых в MP1 нет: стрельба лёжа после шутдоджа,
   last stand, bullet cam.

## Разведка

```
python tools/recon.py "C:\Program Files (x86)\Max Payne" --out recon\mp1
python tools/recon.py "<папка Max Payne 3>" --out recon\mp3
```

Скрипт только читает файлы игры. В каждой папке получатся `recon.md` (сводка
для чата) и `recon.json` (полные данные).

## Сборка

Готовые `.asi` собирает CI: вкладка Actions → последний запуск `build` →
артефакт `maxpayne-passthrough`. Локально (Windows):

```
rustup target add i686-pc-windows-msvc x86_64-pc-windows-msvc
cargo test --workspace
cargo build --release -p mp1phys --target i686-pc-windows-msvc
cargo build --release -p mp3bridge --target i686-pc-windows-msvc
```

Обе игры 32-битные, поэтому плагины собираются только под
`i686-pc-windows-msvc` (под другие цели они пустые).

## Установка

В артефакте CI папки повторяют папки игр:

* **Max Payne 1:** `max-payne-1\scripts\mp1phys.asi` скопировать в
  `<папка игры>\scripts\`. Ultimate ASI Loader (`d3d8.dll`) уже установлен и
  загружает `*.asi` из этой папки — там же лежит
  `MaxPayne.WidescreenFix.asi`. Папка в Program Files требует прав
  администратора.
* **Max Payne 3:** `max-payne-3\mp3bridge.asi` скопировать рядом с
  `MaxPayne3.exe` (`<steam>\Max Payne 3\Max Payne 3\`). Его должен загрузить
  `dinput8.dll` из Script Hook; что это сработало, подтверждает
  `mp3bridge.log`, который появится рядом после первого запуска. Только
  одиночная игра, без сети.

Проверка связи: запустить обе игры. В `mp1phys.log` должно появиться
`Max Payne 3 connected`, в `mp3bridge.log` — `Max Payne 1 connected`.

## Пробы (этап 2)

Плагины сами пишут файлы рядом с `.asi` (при каждом запуске заново):

| Файл | Что внутри |
|---|---|
| `mp1phys.log` | Модули процесса, установка хука, подробности первых 16 вызовов `setBoneMatrices` и первого вызова каждого нового объекта (до 64), каждые 5 с — статистика: вызовы в секунду, число объектов, диапазон числа матриц для двух догадок о раскладке аргумента. |
| `mp1phys.exe-imports.txt` | Импорты `MaxPayne.exe`: `dll имя`, импорты по ординалу — `#n`. |
| `mp1phys.e2mfc-exports.txt` | Экспорты `e2mfc.dll`: `ординал rva имя`, по алфавиту. |
| `mp3bridge.log` | Модули процесса и состояние моста. |
| `mp3bridge.exe-imports.txt` | Импорты `MaxPayne3.exe`. |
| `mp3bridge.scripthook-exports.txt` | Экспорты `ScriptHook.dll`. |

Хук в MP1 перехватывает импорт `MaxPayne.exe` из `e2mfc.dll`
(`P_VirtualObject::setBoneMatrices`), сначала вызывает оригинал, затем
только читает аргумент и пишет лог. В MP3 ничего не перехватывается.

**Выключатель:** пустой файл `mp1phys.nohook` рядом с `mp1phys.asi` — хук не
ставится (в логе будет строка `...mp1phys.nohook exists; not hooking`),
списки и мост работают как обычно. Если создавать файл в Проводнике как
текстовый документ при скрытых расширениях, получится `mp1phys.nohook.txt`,
и он не подействует — проверить по этой строке в логе. Если с хуком игра
падает или ведёт себя странно, сначала сохранить `mp1phys.log` от неудачного
запуска (следующий запуск его перезапишет), потом создать этот файл.

Как прогнать:

1. Max Payne 1: загрузить уровень, где видны Макс и враги, поиграть
   минуту (бег, стрельба, шутдодж), выйти из игры.
2. Max Payne 3: дойти до игрового процесса (не только меню), выйти из игры.
3. Прислать в чат все шесть файлов из таблицы. В них только имена функций,
   адреса и числа из памяти, без кода и ресурсов игры; в репозиторий их не
   коммитить.

В `mp1phys.log` важны строки `hooked e2mfc.dll ?setBoneMatrices@...` (хук
стоит), `setBoneMatrices call ...` (подробности вызовов) и
`setBoneMatrices: ... calls/s` (статистика). Если вместо них
`no e2mfc.dll import starts with ...`, `not hooking` или `cannot patch`, лог
всё равно нужен.

## Правила

В репозитории только свой код. Файлы игр (ассеты, исполняемые файлы, дампы)
не коммитятся: мод работает с копиями игр пользователя.
